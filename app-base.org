* Use make for command runner
Use the following makefile example.  Adjust the commands as needed.

#+begin_src Makefile
  sync:
  	uv sync

  fmt:
  	uv run ruff format .

  lint:
  	uv run ruff check --fix .

  type:
  	uv run ty check

  test:
  	uv run pytest

  check:
  	uv run ruff format --check .
  	uv run ruff check .
  	uv run ty check
  	uv run pytest

  install:
  	uv tool install --editable --force .
#+end_src

* CLI completions
Every app must have a command called =--completions= that is part
of the base command in a click app.

#+begin_example
  command --completions sub-command --some-flag
#+end_example

Only write bash completions.

Write the completion script to =$XDG_DATA_HOME/bash-completion/completions/APP=,
falling back to =~/.local/share/bash-completion/completions/APP= when
=$XDG_DATA_HOME= is unset.  Output the path to the completion script and a
message to source the script so it works in the current terminal.

Bash completion requires bash 4.4 or newer (the generated script uses =compopt=
and =complete -o nosort=) and bash-completion 2.x to auto-load the file.  Warn
when the =bash= on =PATH= is older than 4.4.  On macOS =/bin/bash= is 3.2 and
the default shell is zsh, so document that users need a newer bash (for example
from Homebrew) and that zsh is not covered.  The unsuffixed =APP= filename works
with bash-completion, though versions >= 2.18 prefer =APP.bash=.

* Help
In addition to having =--help= also make =-h= work for help also.

* Configuration
If a config file is needed use a toml file in the
platform's default location.

If a config file is used, add a =--config= option to the base click command
that outputs the path to the config file and exits.

version in the python script.
